## Findings

### Architecture delta

**A1 — E2E suite resets state through the database, not the API (AD-11).** `e2e/tests/view-board.spec.ts:6-9` (and every other spec) seeds and clears through `docker compose exec -T backend python -c …`, importing `app.db.engine` and `app.models.Todo` directly. AD-11 requires E2E specs to be "order-independent and self-resetting via the API". The suite is also serialized (`e2e/playwright.config.ts:5,7` — `fullyParallel: false`, `workers: 1`), which story 1.3 recorded as a deferral, so order-independence is currently enforced by serialization rather than by design. *Disposition: fix now (reconcile to API-based reset) or accept and reconcile AD-11.*

**A2 — `@axe-core/playwright` is a declared dependency with no caller.** `e2e/package.json:10` pins `@axe-core/playwright` 4.13.0; no spec under `e2e/tests/` imports `AxeBuilder`. AD-11 puts axe-core accessibility in the E2E layer. Accessibility was instead verified agentically (`qa/story-1.2.md` … `qa/story-1.6.md`, all Accessibility PASS), so the check exists — but not where the architecture placed it, and not in CI's blocking path. *Disposition: fix now (one axe assertion in the board journey) — small, and it closes an AD.*

Layering (AD-1) holds: `components → hooks/useTodos → api/client` and `routers → services → repository → models` with no sibling imports; `useTodos.ts` is the only caller of `api/client.ts` (AD-6); all SQL is in `repository.py` (AD-9); the only error envelope producers are the three handlers in `backend/app/main.py:39-67` (AD-4).

### Cross-story defect (diff-scope review)

**B1 — A create that settles while a reload is in flight disappears from the board.** `frontend/src/hooks/useTodos.ts:63` rebuilds state as `[...current.filter((row) => row.pending), ...loaded]`. Once `createTodo` resolves, the row is no longer `pending` (`useTodos.ts:109`), so a `load()` promise that resolves afterwards drops it, and the list it carries was fetched before the create existed. The todo is persisted server-side but invisible until the next reload.

Confirmed by execution, not inspection: a temporary Vitest case (retry in flight → `addTodo` resolves → reload resolves with `[]`) observed `active` go from `['buy milk']` to `[]`. The test was removed after the run; it is trivially reconstructable from this paragraph.

This is a boundary defect no single story could see: the merge line is story 1.2's load path, the pending row is story 1.3's optimistic create, and story 1.6's `retry()` is what makes a second load reachable mid-session. Story 1.6 deferred the *duplicate-twin* manifestation of the same line (`spec-1-6-…md:13-21`, severity low); the disappearance case is the more serious sibling and was not recorded. Story 1.3 already flagged that this exact merge is untested — "Reverting the merge back to `setTodos(loaded)` leaves all 17 frontend tests green" (`spec-1-3-add-a-todo.md`). Against NFR-2 ("no silent data loss — the user always knows when an action failed") this is the one finding worth calling a defect. *Disposition: fix now.*

### Duplication map

**C1 — The E2E seed/clear prologue is copy-pasted across the suite.** The first 30 lines of `complete-and-delete.spec.ts`, `create-todo.spec.ts` and `empty-state.spec.ts` are byte-identical (md5 `26a6d8d2…`), with near-identical variants in `view-board.spec.ts` and `error-handling.spec.ts` — ~150 duplicated lines total, one copy per story session, no shared fixture. *Disposition: fix now — extract `e2e/tests/fixtures.ts`; it also gives A1 a single place to change.*

### God-file / size growth

**D1 — `backend/tests/test_health.py` became the backend's catch-all.** 312 lines, top of the churn ranking (`added: 334` across 4 commits) for a file whose stated job in the epic's test table is two health cases. It now also holds `Settings` defaults (`:33`), the whole error-envelope probe app and its five routes (`:45-93`), session-commit behaviour (`:223`), camelCase/UTC schema serialization (`:238-289`) and `init_db` idempotency (`:291`) — while `test_errors.py` (38 lines) and `test_schemas.py` (20 lines) exist and are where a reader would look. The `error_client` fixture at `:45` also declares its imports inside the function body and returns an `AsyncClient` that is never closed, unlike the `async with` fixture in `conftest.py:25-29`. *Disposition: fix now (split by subject; move shared fixtures to `conftest.py`).*

`frontend/src/App.test.tsx` is the other large file (544 lines) but reads as one coherent component suite; noting it as a watch item, not a finding.

### Pattern divergence

**E1 — Deferred items accumulate in story frontmatter with no aggregation.** 17 `deferred` entries across the six specs (1-1: 5, 1-2: 2, 1-3: 4, 1-4: 2, 1-5: 2, 1-6: 2), every story carrying `followup_review_recommended: true` and `warnings: [oversized]`. Nothing outside the story files tracks them, so a defect deferred twice never escalates — the `--color-text-done` / `--color-control` contrast shortfall was deferred independently in 1-1 and again in 1-4 and is still live (`frontend/src/styles/tokens.css:5,9`). *Disposition: process lesson — surface deferrals into `sprint-status.yaml` action items at story close.*

**E2 — Frontend "lint" is a typecheck only.** `Makefile:26-28` runs `ruff check` + `ruff format --check` on the backend and `npm run lint` on the frontend, which is `tsc --noEmit` (`frontend/package.json`). AD-13 names a `lint` target; it is asymmetric, and story 1.1 already deferred it. *Disposition: defer (accepted deviation, now recorded once at epic level rather than per story).*

### Spec-to-implementation reconciliation

**F1 — Responsive breakpoint off by one against UX-DR9.** UX-DR9: "≥640px two equal columns … <640px stacked". `frontend/src/styles/app.css:141` uses `@media (max-width: 640px)`, so at exactly 640px the layout stacks. *Disposition: fix now — one character.*

**F2 — Contrast tokens below WCAG AA, as designed.** `--color-text-done: #555555` (~2.8:1) and `--color-control: #444444` (~2:1) on `#000000`. These are DESIGN.md values and NFR-5 makes WCAG 2.1 AA a stretch goal, not a gate; completion is also conveyed by column, checkbox and strikethrough, so NFR-5's floor holds. *Disposition: accept as-is — recorded so later retros stop re-flagging it; revisit if AA ever becomes a gate.*

**F3 — Six story PRs are still open on GitHub.** `gh pr list` shows PRs #1–#6 OPEN, each targeting the previous story branch, while the same commits are now merged into local `main` (unpushed). The stacked-PR DoD was met per story; the epic-level close-out is not. *Disposition: fix now — push `main` and close the stack.*
